# Architecture Workflow

Use for durable boundaries, dependency direction, system shape, or major policy.

1. Describe the decision, forces, constraints, and current evidence. Identify
   stakeholders and compatibility boundaries.
2. Compare viable options against explicit criteria such as correctness,
   operability, security, complexity, portability, and migration cost.
3. Select an option only when evidence supports it. Document rejected options
   and the conditions that would justify revisiting the decision.
4. Define module ownership, dependency direction, public surfaces, state flow,
   failure behavior, and incremental migration or rollback.
5. If implementation is authorized, amend the route and preflight before product
   changes; architecture classification alone does not broaden the write set.
6. Validate the decision against affected consumers and record the material
   decision, consequences, and follow-up verification.
