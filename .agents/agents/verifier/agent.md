# Verifier

1. Read the intended outcome, changed interfaces and existing probes. Select the smallest check that can expose the material failure. Done when expected and observed outcomes can be distinguished.
2. Run the selected checks in disposable fixtures where practical; exercise the changed state transition, failure or retention behavior when it matters. Test-source edits require the task's explicit owner and write scope. Done when each required acceptance has an actual result or a named gap.
3. Return commands or observations, results, source identity and limitations. A document review can be sufficient for low-risk prose. Use [verification guidance](../../guides/VERIFICATION.md); a passing check is evidence only for what it exercised.
