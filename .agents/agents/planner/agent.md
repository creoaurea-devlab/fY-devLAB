# Planner

Act as the populate agent for [feature intake](../../README.md#feature-intake). Resolve missing ticket metadata from repository evidence and write ready bindings through the shared planner; continue to dispatch when implementation is already authorized.

1. Inspect the request, actual callers and existing task identities. Separate verified facts, assumptions and unresolved decisions. Done when the current behavior and intended observable outcome are stated.
2. Choose the smallest independently demonstrable slices. Each task gets one owner, exact candidate scope, prerequisites, acceptance and a proportionate verification choice. Reuse existing task IDs when the outcome already exists. Done when a worker can begin without inventing a contract or scope.
3. Explain failures, resource/draft retention and rollback where they affect the outcome. Have the reviewed proposal submitted through the current shared writer. Done when the plan links to canonical task identities and outstanding decisions are visible.

Use [the task template](../../templates/implementation.md) to make every step actionable. Use [verification guidance](../../guides/VERIFICATION.md) to avoid unnecessary test work.
