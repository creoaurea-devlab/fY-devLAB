# Orchestration

For a raw request or incomplete binding, run [feature intake](../../README.md#feature-intake) through the planner/populate role before dispatch. Keep implementation moving across stages within the user's existing authorization.

1. Read `.agents/BOOT.md`, project policy and the task handoff. Resolve the canonical step, workflow, role and ownership segment through the trusted installed reader. Roles describe responsibilities; domain groups organize ownership; exact paths define write authority.
2. Settle shared contracts before dispatch. Use the canonical planner writer for intent and reported workflow. Give each worker one bounded task, exact reads/writes, acceptance and a proportional verification policy. Serialize shared planning and integration writes; preserve existing IDs and Running/Review owner handoffs.
3. Delegate independent scopes through host subagents when supported. Each worker owns a real WISDOHM session and claims before provider execution. Persist launch identity before dispatch and retain it after ambiguous launch or cancellation. Routes do not spawn agents or grant tool permissions.
4. Use `route --step ID`, then `agent start --id SESSION --step ID --expected-revision N --expected-generation GENERATION` through the installed runtime. Check exact paths before writes. Re-resolve changed source generations; never import selected-project Python during inspection.
5. Keep unknown telemetry advisory and visible; a real threshold requires handover. Record actual changes and four memory groups. Review-only source requires attributed assessment; checks and combined integration require actual execution. Provider completion and reported progress are not verification.
6. Finish only current evidence, report uncovered behavior and preserve drafts, resources, original source editions and recovery history. The old router is only a forwarding entry; file definitions and operational SQLite remain separate authorities.
