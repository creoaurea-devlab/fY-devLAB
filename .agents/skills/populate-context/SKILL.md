# Populate project context
For feature requests and incomplete bindings, execute the PLAN stage of [feature intake](../../README.md#feature-intake). Discover and fill behavior, acceptance, exact owner paths, prerequisites, implementation instructions and verification policy; use existing conventions for reversible choices. Return ready canonical task identities to the coordinator automatically. Scope discovery is read-only until metadata writes have their own declared owner session.

1. Resolve the explicit target and read its active agent entry. Use the installed setup review/repair flow when the agent home is missing. Preserve the independent runtime release source.
2. Inspect relevant source, package commands and public consumers. Reuse current codebase observations; refresh only affected facts. Record uncertain facts as assumptions until they affect acceptance or safe ownership.
3. Populate selected configuration and ownership segments from that evidence. Each source path has one capability owner, public seams and acyclic dependencies. Groups organize navigation; workflows select roles; domain skills supply local guidance. Preserve explicit user settings and existing work.
4. Use the shared revision/digest-checked planner for task definitions and reported progress. Every task has one folder and the shared implementation template. Declare exact configuration/ownership writes in a governed owner session; check them before editing. Existing authorization applies; ask only for an unresolved decision needed to proceed safely.
5. Validate selected definitions and affected references. Review suitable prose directly; run meaningful checks for executable changes. An observation, report or imported history is distinct from current execution evidence.
6. Record actual source facts, changes and progress through operational memory, review affected groups, and finish with required evidence. Return changed paths and any real limitation.
