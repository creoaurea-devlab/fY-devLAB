## Invariants, hidden moving parts and failure cases to decide explicitly

1. **Two revision levels + release identity:** project revision is storage conflict stamp; draft revision binds proof/review; semver is per-capability accepted baseline. Do not conflate them with repository commit/version. Failed persistence still mutates in-memory state and event/revision (A22–26). Production must commit state+events/snapshot together or leave canonical state unchanged, and reject stale expectedRevision. C155–180 is a proposed contract, not installed implementation.
2. **Historical fidelity is incomplete:** A113 copies only blocking edge records, no target release pins, despite D29 and README prose suggesting exact dependency context. Context export A119 adds targetReleaseId from *live* current baselines. Snapshot read-only UI loads rule detail through live `rule(id)` (A103–104,114), which imported contradictory snapshot/global definitions could expose. Preserve snapshot definitions and exact dependency targets via an explicit schema decision/migration.
3. **Source vs latest:** from a work node/drawer, A68–70 branches the entity's latest accepted baseline, not that draft's edits. Unreleased entity baseline remains its initial entity blueprint. Variant dependency copying uses live `deps(parent.id)`, not source snapshot edges; UI hierarchy flattens every inherited parent to workspace. Decide faithful parity or intentional correction with tests. parentReleaseId is provenance; supersedesReleaseId is replaced current baseline. Graph lineage currently labels parent relation “superseded by” (A76); old-source release can differ from replaced latest.
4. **Release policy nuance:** demo evidence cannot pass releaseGate, but a demonstration currentRelease *does* satisfy prerequisite existence. Any current failed proof blocks forever at that revision; adding a pass does not override failed entry and there is no retraction. Only edits produce a fresh revision. Empty tasks fail; archived cards are not explicitly rejected by recordRelease; qa stage not required. Evidence is manual, not proof the command ran. Decide how target governance evidence relates without inventing CI.
5. **WIP/scope/stage:** global active WIP excludes archive/filter; adding dependency can demote multiple source drafts; related links do not invalidate; snapshot membership and dependency changes need one revision policy. Restore bypasses demotion by setting Plan. Stage movement is intentionally non-sequential. New column plus always Plan.
6. **Import validation is basic:** 8MB and top-level global IDs (not nested task/UI/decision IDs), selected field types/references, ownership/current release ownership and live-edge cycles are checked. Not all strings/dates/enums/booleans/nested limits, task IDs, review/evidence sources, release.cardId, card.releaseId consistency, done→snapshot, source release ownership, derivedFrom, supersedesReleaseId, rule-version uniqueness/format, snapshot dependency/rule completeness or UI-parent cycles are validated. Duplicate live edges are allowed on import. Seed's demo Done has null manual review; never infer real completion. Empty-entity v2 allowed. Validation then replacement failure must retain current project byte-for-byte, including corrupted imports/cancel/oversize.
7. **Concurrent safety is only advisory:** cross-tab event ignores same-revision divergence, key removal/clear, distinct project IDs and close races. It pauses only after a difference event; compare-before-write/CAS absent. Reset brings revision back to seed1, so equal stamp collision possible. No merge/lease/worktree/runtime enforcement. D77–91 calls these future upgrades.
8. **Data-loss/accessibility:** rerender destroys active unsaved forms/disclosure state on tabs, graph navigation, imported data, archive, modal dismissal/escape and storage events. Existing source has no dirty guard. Parent should specify one drawer unit owning draft edits, scroll/focus, unsaved guard and cleanup; nested modal focus must return within drawer then invoking card. Keyboard stage selector substitutes for drag, while touch drag isn't established. Tiny pale-text screenshot is reference, not accessibility certification. No external services/links are executed by app; only home #, local Blob and reload. D105/109 contain optional external architecture references; not opened in this audit.
