# PROTOTYPING and SPEC Agent

The existing UI preview is the named PROTOTYPING feature, owned by preview-view.
Stable markers and the visible label identify it without changing its frame/editor owners.
SPEC_AGENT is a separate feature owned by spec-ui. Workspace and Planning entry points
use the existing single inspection/focus owner; returning opens the existing Planning view.
The frontend implementation owner uses the browser profile; a separate specification
profile/skill describes the read-only generation role.

The user describes a feature, explicitly starts installed Codex through an owned terminal,
reviews the generated structured specification, and separately approves adding its
milestone/slices/atomic tasks to Kanban. No provider runs on mount. The selected project's
file service safely creates a unique artifact before the CLI writes its final response.
The prompt is encoded into bounded ASCII PTY lines; no bypass flags or Git operations.
Read-only mode and proposal instructions are not universal tool-confinement certification.

Validate bounded JSON, exact declared owners and paths, checks, acceptance and unresolved
questions. Questions prevent import; unsupported/blocked research may return questions
without inventing tasks. Preserve prior plans and progress through the existing CAS writer.
Retain the exact first command envelope for ambiguous-response retry. Changing a build
request invalidates its review; artifacts remain available. Cancellation closes only the
owned generation terminal and reports failure honestly. Draft requests are project-scoped.

Acceptance covers real PTY execution with an explicit fixture Codex executable, review
before import, existing definitions and resource retention, native keyboard/focus/Escape,
provider errors, cancellation, hostile input and stale review/retries at1440/820. An actual
installed-Codex connectivity probe is separate from the boundary-stub browser tests;
no production specification-generation quality claim is inferred from either.
